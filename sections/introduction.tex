\section{Introduction}
\label{sec:introduction}

Static analyzers remain one of the few security tools that scale to enterprise codebases, but their conservative approximations impose a large human triage burden. Industrial studies report false-positive (FP) rates of 40--90\%~\cite{johnson2013,christakis2016}, and manual review commonly costs 10--20 minutes per alert~\cite{tencent2023}. The resulting alert fatigue is not merely inconvenient: it determines whether organizations can keep analyzers enabled broadly enough to catch real vulnerabilities.

LLMs offer a plausible way to reduce this burden because they can read analyzer evidence---code slices, data-flow traces, path constraints, and SARIF metadata---and explain why an alert is likely a true positive (TP) or FP~\cite{llm4fpm2024,llm4pfa2024,buglens2024,adataint2023}. The central problem is not whether LLMs can classify alerts at all. It is whether a software organization can safely automate any part of triage when the model is cheap enough to run at scale. Our measurements show two barriers. First, lite models collapse under zero-shot calibration: in Study~1, five lite LLMs evaluated on Juliet alerts spanning 87+ CWE classes reach only 42.2--59.9\% precision, with ECE above 0.35 for every model. Second, existing LLM triage systems usually force a binary decision. That is the wrong abstraction for security triage, where the cost of auto-dismissing a real vulnerability exceeds the cost of sending an uncertain alert to a developer.

We introduce \textbf{EVICT} (Evidence-Conditioned Investigation with Calibrated Triage), which reframes static-analysis alert triage as \emph{cost-sensitive selective prediction}~\cite{elyaniv2010,geifman2017}. EVICT learns a predictor $h$ that proposes TP or FP and a rejector $g$ that decides whether to commit or abstain. The system accepts an alert only when calibrated evidence supports a reliable singleton decision; otherwise it defers the alert to human review or conditional symbolic escalation. This design makes abstention a first-class, auditable action rather than an implementation detail hidden inside a confidence threshold.

The liquid-gold finding of this paper is that \emph{the bottleneck is the confidence signal, not the conformal algorithm}. In Study~2, six models spanning reasoning, instruction-tuned, and code-specialized training paradigms are evaluated on the same 247-alert Juliet conformal benchmark with $k_{\mathrm{sc}}=5$ self-consistency samples and $F=5$ cross-validation folds. R1-Distill-14B, a 14B reasoning model, produces 36\% unanimous vote-share and ECE 0.335. Larger or code-specialized non-reasoning models produce 85--98\% unanimous vote-share and ECE 0.51--0.62. With only six models, this is an effect-size pattern rather than a population-level causal law; mechanistically, it is consistent with reasoning traces inducing genuine disagreement across samples when evidence is ambiguous.

The strongest causal evidence comes from Study~4, where we hold Gemini 2.5 Flash Lite fixed and change only the prompt. A contrastive prompt that forces the model to argue both TP and FP before deciding reduces unanimity from 84.6\% to 16.2\% and ECE from 0.555 to 0.337 on the same 247-alert CWE-89/78/190 subset. The contrastive prompt produces more diverse confidence than the 14B reasoning model under the default prompt (16.2\% vs. 36\% unanimous), showing that prompt design can substitute for model scale in producing a calibratable self-consistency signal.

We also find a deployment-relevant code-specialization paradox. In Study~3, on 549 real CodeQL alerts from 45 CWE-Bench-Java projects with a 97\% FP base rate, DS-Coder-V2-Lite achieves the highest precision (4.0\%) and true-negative count (184), despite having the worst Juliet confidence quality in Study~2 (98\% unanimous, ECE 0.620). Code-specialized models appear better at recognizing safe code patterns but worse at quantifying uncertainty, suggesting a two-stage design: use a code model as a semantic classifier and a reasoning or contrastive-prompted model to provide a calibration signal.

This paper makes the following contributions:
\begin{itemize}
\item We formalize alert triage as cost-sensitive selective prediction with asymmetric security costs and finite-sample guarantees for pre-escalation conformal prediction.
\item We present EVICT, a four-stage framework for SARIF evidence extraction, schema-guided LLM verification, conformal singleton-reject calibration, and conditional symbolic escalation.
\item We report real multi-model measurements showing that self-consistency confidence quality is associated more strongly with training objective than model size in our six-model conformal study.
\item We introduce contrastive alert-triage prompting, a model-fixed intervention that reduces Gemini 2.5 Flash Lite ECE by 39\% and vote unanimity by 68.4 percentage points in Study~4.
\item We validate on real CWE-Bench-Java CodeQL alerts and identify the code-specialization paradox as a practical design constraint for LLM-based alert triage.
\item We release an anonymized artifact plan covering code, prompts, logs, and an unrun frontier-model harness so groups with higher API budgets can evaluate the projected frontier outlook.
\end{itemize}
