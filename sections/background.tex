\section{Background and Related Work}
\label{sec:background}

\subsection{Static Analysis and Alert Fatigue}

Static analysis scales because it over-approximates program behavior, but the same conservatism produces large numbers of FPs. Empirical SE studies document why developers often ignore or disable static-analysis warnings: warnings arrive without enough context, many are not actionable, and review cost competes with feature work~\cite{johnson2013,christakis2016}. Industrial deployments report the same operational pressure at scale~\cite{tencent2023}. A triage system for this setting must therefore optimize more than accepted-alert precision. It must reduce developer review burden while controlling unsafe auto-dismissals.

\subsection{LLM-Based Alert Triage}

Recent systems use LLMs to interpret static-analysis evidence. LLM4FPM, LLM4PFA, BugLens, and AdaTaint show that grounding model reasoning in paths, call chains, or taint information improves FP mitigation over evidence-free prompting~\cite{llm4fpm2024,llm4pfa2024,buglens2024,adataint2023}. EVICT shares the premise that analyzer evidence is essential, but differs in the decision abstraction: it does not ask the model to always choose TP or FP. Instead, it accepts only calibrated singleton decisions and routes the rest to abstention.

IRIS is the closest conceptual neighbor~\cite{li2025iris}. IRIS uses LLM-assisted specification inference to validate CodeQL findings and is well matched to frontier-model reasoning with per-vulnerability formal specifications. EVICT targets a different deployment point: cheap lite and open models, SARIF-derived evidence packs, and principled abstention without requiring a formal specification for every alert class. A direct head-to-head comparison on identical CWE-Bench-Java CodeQL alerts is ongoing future work rather than a reported result in this submission.

\subsection{Selective Prediction and Calibration}

Selective prediction formalizes the option to reject uncertain examples~\cite{elyaniv2010,geifman2017}. This is a natural fit for static-analysis triage because abstention corresponds to ordinary developer review, not system failure. Calibration is necessary because LLM confidence is often misaligned with correctness~\cite{guo2017calibration,kadavath2022,guo2024calibration}. Split-conformal prediction provides finite-sample marginal coverage under exchangeability for any nonconformity score~\cite{vovk2005,angelopoulos2021}. EVICT uses this standard guarantee in a software-engineering-specific way: conformal sets are converted into TP/FP/ABSTAIN decisions via a singleton-reject rule.

\subsection{Neuro-Symbolic Verification}

Symbolic execution and model checking can prove path feasibility or discover counterexamples, but universal symbolic analysis is expensive and brittle on large applications~\cite{jpf2003,spf2013,klee2008,laurel2022}. EVICT uses symbolic engines conditionally: Z3, Java PathFinder, or KLEE are invoked only for abstained alerts or high-severity dismissals requiring audit. This separation is important. The conformal guarantee applies before escalation; symbolic verification is a post-calibration audit layer whose results must be measured separately or recalibrated if used as a new confidence-producing stage.
